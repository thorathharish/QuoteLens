# Demo data

Generated by [`services/api/scripts/generate_demo_data.py`](../services/api/scripts/generate_demo_data.py) from the declarative definitions in `services/api/scripts/demo_data/`. **Don't edit these files by hand.** Change the definitions and regenerate:

```bash
cd services/api
uv run python scripts/generate_demo_data.py          # regenerate
uv run python scripts/generate_demo_data.py --check  # CI test: fails if outputs are stale
uv run python scripts/load_catalog.py --dry-run      # validate against the row models
uv run python scripts/load_catalog.py --project <gcp-project>   # load into BigQuery (free load jobs)
```

## What is real and what is synthetic
| Data | Real or synthetic |
|---|---|
| Manufacturer part numbers, manufacturers, descriptions, packages, key parameters | Real public part identities (parameters simplified) |
| **Prices, stock, MOQ, lead times, lifecycle status, LTB dates** | **Synthetic.** Illustrative values for the demo, *not* real distributor or manufacturer data |
| Distributor offers | Use real distributor *names* for realism, but every SKU starts with `DEMO-` and every row has `mode = DEMO_SNAPSHOT` |

The UI shows `DEMO_SNAPSHOT` on every value from this catalog. When distributor API keys are configured (Phase 3, P1), live offers (`mode = LIVE`) replace the synthetic ones.
